Enemy flow
----------
AP client publishes two 32-bit enable words at RDRAM 07F300/07F304 in a menu.
Enabled is 00004153; disabled is zero. There are NO Python enemy mappings,
per-type substitutions, per-character Python tables, or enemy seed hashing.
Music retains the previous independent AP-slot mapping.

The four native ROM hooks check their switch. Disabled hooks tail-call the
original function without drawing randomness. The first enabled hook copies
1536 bytes of native code/data from ROM BFF000..BFF600 into 8007F400..8007FA00.
That ROM range was verified FF padding. The RAM is inside the already reserved
portal-queue tail, not an allocation borrowed from the stage heap. The first
instruction is initially zero in BSS and acts as the one-time load marker.
Later enabled hooks enter the already-loaded code. No Python executable-code
transfer is required. The original portal queue remains capped at 376 entries.

Native selection lives in native/enemy_randomization.c. ABI wrappers are in
native/enemy_hooks.s; the compiler produces native/enemy_randomization.bin.
The four entry addresses are fixed by those assembly wrappers:
  setup appearance   8007F400
  dynamic appearance 8007F444
  setup weapon       8007F488
  scripted weapon    8007F4EC
The payload calls vanilla randomGetNext at 7000A450. Every eligible creation
gets a fresh draw. Identical original bodies and weapons do not share a pick.
Coincidental repeats are normal. Retries/reloads can reroll; this is no longer
an AP-seeded enemy layout. Normal game RNG consumption changes when enabled.

Appearances
-----------
Use Random-eye-zer's 36-body pool and native male/female head pools. Each
creation draws body % 36, then an appropriate separate head, or -1 for bodies
with built-in heads. Model arguments AND caller body/head locals are updated.
Character IDs, AI, positions, objective tags and AP check IDs remain native.
Both setup and dynamic actors are covered. The broad character hooks also
cover scripted NPCs/allies. Bond's separate construction path is described below.

Bond's model
------------
ROM AEAD0 calls wrapper 03E460 and payload 8007F780 in single player only.
It chooses cuffs 0..7, then the same 36-body/compatible-head selection as the
hack, and updates the original caller's body/head locals at sp+44/sp+40.
The game still constructs and renders the actual model. This changes a 3D
model, not a flat sprite or an enemy-class lookup. Multiplayer stays native.

The vanilla player loader assumes a separate head. Random-eye-zer adds a
built-in-head branch; simply passing head=-1 would index before the model
table. ROM AEB94 now calls wrapper 03E428 / payload 8007F800. For a separate
head it returns the original body-file length and continues normally. For
head=-1 it copies the hack's body-only allocation and animation layout,
sets the head-header pointer to NULL, and resumes at native 7F07A234.
The support code is native/enemy_randomization.c:prepare_bond_body.

Loadouts
--------
Use the hack's 16 unconditional weapon/model pairs: Golden Gun, rocket
launcher, grenade launcher, shotgun, Cougar Magnum, auto shotgun, sniper,
RC-P90, AR33, Phantom, D5K, ZMG, KF7, Klobb, DD44 and PP7.
Each eligible creation draws RNG % 16. Unlike the hack's 19-entry gated
retry loop, this omits its disabled Silver/Gold PP7 and Moonraker Laser entries
up front; the available pool is the same as its default enemy weapon pool.
Eligibility follows its input whitelist: IDs 2..25, 30 and 31.

The previous one/two-handed pool partition and Train/Caverns class mappings
are removed. Both hands independently select a matching model/weapon pair.
The setup hook runs only in the assigned-to-character branch. Native hand
flags and original creation calls are preserved. This does not force a second
weapon into an empty hand, add player starting weapons, or grant AP ownership.
Native drop/pair behavior after combat still needs gameplay validation.

Explosive replacements can damage mission objectives. We have NOT imported
the hack's Caverns invulnerability edits or Train AI timing edits. Those
missions and other objective-sensitive encounters need playthrough testing.
This is a candidate, not a full mission-safety certification.

Memory and hook layout
----------------------
The initial 4 MiB experiment reproduced a Dam load failure. The 8 MiB candidate
loads all 36 original Dam guards, with 27 distinct bodies in the appearance-only
capture. This adopts the original hack's upper-memory layout instead of
restoring the per-body restriction.

24 verified LUI words move boot/thread stack and framebuffer addresses up
400000, including the TLB arena boundary. The native stage heap extends to
that arena and therefore receives the extra memory. The mapping/heap logic
is otherwise native. address_map.json includes every differing word, including
these memory changes, payload, hooks and recalculated header checksums.

Purpose           ROM     original JAL  replacement JAL   ROM wrapper
Setup appearance  058310  0FC08D34      0FC02633          03E3FC
Dynamic actor     068D18  0FC08D34      0FC02641          03E434
Setup weapon      037314  0FC015C4      0FC02682          03E538
Scripted grant    086F10  0FC14885      0FC0269C          03E5A0
All original delay slots remain. Each wrapper is 44 bytes. The ROM-copy helper
is 60 bytes at ROM 03E564 / virtual 7F009A34. DeathLink's delay slot at 03E534
and the surrounding AP cheat/ownership helpers are preserved.

The client checks the enemy JAL signatures, the 4153 gate, global SFX entry
and both Bond model/allocation hooks.
Older clients use 4150 or 4152 and cannot enable this new payload accidentally. Current
clients reject the old mapping ROM. Use matching package and ROM.

Music
-----
Independent AP seed/slot mapping and a fixed per-mission selector table.
Primary cost fits 6344 bytes;
secondary cost fits 2000 bytes with 16 attempts and fallback 18 hex. Native
secondary exceptions for stages 23/2B hex and -1 entries remain. Watch music
and background sound fields remain native.

Intro (2), folders/menu (23) and intro swoosh sequence (44) are also donors
and randomized recipients. Rom.py writes a 63-word table at ROM BFED00 from
the independent frontend-music-v1 seed stream. Seven frontend calls at ROM
03F794,03FCA0,0405A8,0429B8,0452C8,04AC18,04D240 enter wrapper 03E5FC and
helper 8007F740, then tail-call musicTrack1Play(70006E7C) with the selection.
Mission calls are not routed through this map, so music is not remapped twice.
The intro works before client connection. Off uses an identity table.
All slot-specific tables are outside the N64 checksum region; no room-specific
checksum extension or host-side vanilla ROM is needed during generation.

Weapon firing sounds
--------------------
The client writes firing selectors at guarded menu boundaries. Twenty-four
WeaponStats.Sound entries cover IDs 4..22, 24, 31, 32, 35 and 36. The shared
native getter serves player and enemy firing. The nineteen sound choices are:
0001 000B 000C 002E 005C 005D 0064 006A 006B 006D 006E 006F 0070 0071
0074 0075 0079 00E4 00FD. This includes rockets, grenade/tank launchers,
watch/military lasers, shotgun and RC-P90. Native taser shot 0064 finishes;
0065 is its held loop. Earlier research confused zero-based bank array indices
with one-based playback IDs. No sound-bank or sample modification is required.
Address = physical RDRAM 03267A + (weapon ID - 4) * 70 hex.
Selections are stable for the AP seed/slot, using weapon-firing-audio-v2.
Each enabled weapon excludes its own original sound from its choices.
The watch laser's separate two-entry table at 80035E90 receives one shared
selection; off restores 005C/005D. Rocket selector 8007F310 holds the selected
sound, or 0001 when off. Its 28-byte helper at ROM 03E5CC / VA 7F009A9C
replaces only a1 and tail-calls sndPlaySfx. Zero retains native a1 for a boot
without a connected client. Player rocket calls 094ABC/094AE0 and enemy
rocket calls 0628D8/0628FC enter this helper, retaining projectile handles.
Off restores canonical defaults. Firing timing, handles, AI hearing, damage,
reloads, impacts, explosions and bank data remain native. Grenades/mines and
melee do not have gun firing reports; this option does not remap their other
sound events. Source-only flare/piton stats are also covered by the table.
Updated ROM AND client are needed for rocket coverage. Older ROMs have no
rocket hook. Existing online rooms retain their old downloadable patch.

Current fixture: run_extended_randomization.py CASE. Older audio trace scripts
overwrite wrappers now used by global SFX/music and must only use their frozen
historical snapshots. RAM 07F800 now belongs to the Bond allocation helper.

All sound effects
-----------------
randomize_all_sfx replaces randomize_grunts. All 261 audible playback IDs
(1..261) participate; zero remains silence. Runtime sndPlaySfx indexes the
instrument at +12+ID*4, while its file array starts at +16. ID 261 is valid.
Rom.py classifies complete chains: 241 self-finishing and 20 held effects.
Each group is shuffled into a cycle, so every audible ID changes within its
stop behavior. Chains, sample envelopes, handles and positional audio remain
native. No weapon sound is excluded from the global map.

Rom.py:build_rom_audio writes the 262-word table at ROM BFE800. The central
sndPlaySfx entry at ROM 009A08 jumps to wrapper 03E5EC / native 8007F700.
It maps a1, replays the displaced prologue and resumes at 70008E10. The
internal sound replay caller 700088C8 bypasses mapping to avoid a second
substitution. The old death-only hooks at 05BCF4/05BD5C are gone.
Gun SFX selector writes restore vanilla when All SFX is enabled, so every
sound receives exactly one substitution. The table works before connection.

Existing rooms retain their older .apge and option names. Generate a new room
with the matching current apworld to use this replacement option and the
seeded intro/menu tracks. The generic ROM contains identity audio maps.

Facility texture correction, 2026-10-05
--------------------------------------
The original port expanded the stage heap but omitted Random-eye-zer's
minimum 2 MiB texture pool (hack VA 7F007470..7F007484). Facility retained
its 650 KiB budget. With independently randomized bodies/heads it reached
1,160 bytes free, below texLoad's 2,600/4,300-byte minimum. The native
out-of-space path substitutes the pool start address as texture data.
This produces corrupt textures immediately, including on equipped hats.

USA ROM 03BEA4: 8C849170 -> 3C040020 (allocation size = 2 MiB).
USA ROM 03BEB8: 8CC69170 -> 3C060020 (same texInitPool boundary).
The fixed Facility run retained 862,264 bytes free after loading. This
matches the original hack's effective budget for vanilla stage settings.
Character and hat selections are unchanged. Native global 'bytes' still
contains the original stage budget; the actual pool bounds use 2 MiB.
Room download base_patch.bsdiff4 must be rebuilt for these ROM edits.
An already generated room contains its older patch until regenerated;
a separately corrected ROM can retain the existing room identity.
